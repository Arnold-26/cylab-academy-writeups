```python
pride    = 16 caracteres aleatoires de [ascii_letters+digits]     # le mot de passe
```

On recoit **`c` et `d`** (jamais `n`). « SRA » = RSA à l'envers.

## Attaque

`e·d − 1 = h·φ(n) = h·(p−1)(q−1)` avec `h < e = 65537` (car `d < φ`).

1. `K = 65537·d − 1` (~270 bits).
2. **Factoriser K** : division par les petits premiers (< 10^6), puis **ECM** (`gmp-ecm`, binaire
   `ecm` déjà présent dans Kali) par paliers `B1 = 11k, 50k, 250k, 1M`. Sur l'instance réelle,
   un facteur de 36 bits puis un de 63 bits sont tombés en **1 seconde**.
3. `(p−1)(q−1) = K/h` : répartir les facteurs premiers de K entre `A = p−1`, `B = q−1` et `h`
   par **DFS avec élagage** (facteurs triés décroissants) :
   - `A, B < 2^129` (p, q sont des premiers de 128 bits), `A, B ≥ 2^127` ;
   - `h < 65537` ;
   - élagage : `A·(produit restant) < 2^127` -> inutile de continuer.
   Sur l'instance : 11 facteurs, 7 683 nœuds, 1 192 splits candidats.
4. Pour chaque split : `p = A+1`, `q = B+1`, vérifier la primalité, `n = p·q`,
   `m = pow(c, d, n)` ; on garde la valeur qui donne **16 octets alphanumériques**.

Résultat : `Uld7A3cY6y1gs744` -> `Conquered!` + flag. Durée totale : **2 secondes**.

## Leçon

Donner `d` (et `e`) sans `n` ne protège rien : `e·d−1` est un multiple de φ(n), et sa
factorisation (partielle) suffit à reconstruire `p` et `q` dès que `p−1`, `q−1` n'ont pas de
très grand facteur premier. C'est une attaque sur la **taille des facteurs de p−1/q−1**, pas
sur RSA lui-même.
