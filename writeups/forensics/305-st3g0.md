# 305 — St3g0

**Événement** : picoCTF 2022 · **Catégorie** : Forensics · **Auteur** : non précisé dans les sources consultées

> Synthèse rédigée à partir des sources publiques listées en fin de fiche : ce challenge a été
> résolu côté CyLab Academy, mais le writeup d'origine n'a pas été conservé.

## Énoncé

« Téléchargez l'image et trouvez le flag. » Le fichier fourni s'appelle `pico.flag.png` et
affiche une image anodine comportant le texte « PICO » — aucun flag visible à l'œil.

## Analyse

PNG + indice « st3g0 » ⇒ stéganographie dans les **bits de poids faible** (LSB) des pixels.
L'ordre de lecture et le canal utilisé doivent être déterminés ; tester à la main
(`zsteg` sans option, `stegsolve`) peut échouer et faire perdre du temps.

Un premier essai avec un décodeur LSB en ligne (« Steganography Online ») ne donne rien : ces
outils n'essaient qu'une combinaison (souvent `b1,rgba,lsb,xy` sur 4 canaux), alors que
l'image encode le message sur 3 canaux (RGB, sans alpha) — d'où l'échec.

## Solution

Balayage exhaustif de toutes les combinaisons connues avec `zsteg` :

```bash
zsteg -a -v pico.flag.png
```

La sortie révèle le flag sur la ligne étiquetée **`b1,rgb,lsb,xy`** :

- `b1` : 1 bit par canal ;
- `rgb` : canaux rouge, vert, bleu (alpha ignoré) ;
- `lsb` : bit de poids faible d'abord ;
- `xy` : parcours des pixels de gauche à droite, ligne par ligne.

Extraction ciblée, une fois la combinaison connue :

```bash
zsteg -E "b1,rgb,lsb,xy" pico.flag.png
```

Leçon : sur un challenge LSB, toujours commencer par `zsteg -a` (toutes les méthodes) plutôt
que par un outil en ligne mono-combinaison.
